# 表格回写与状态机（table-writeback）

本文件规定**授权回写**来源表格时的契约。SKILL §0.2 的"原始资料只读"是默认值；
只有用户明确授权后，才按本文件的范围回写，且**范围不得扩大**。

---

## 1. 状态机

状态列（本类表格的 B 列「状态」）是三态，**只前进、不回退**：

```
未写作  ──稿件+网页交付──▶  已写作  ──自媒体已发出 且 网页已上线，两个链接都到位──▶  已发布
```

| 状态 | 触发条件 | 同一动作里同时写什么 |
|---|---|---|
| （空） | 表格原样 | — |
| `已写作` | 该行稿件**已交付**：正文文件 + 稿外说明（来源清单、启用依据、缺料说明、核心问题）+ 自检结论（+ 网页文件） | 编号列 |
| `已发布` | **自媒体链接与网页链接都拿到并验证过**（不是"点了发布按钮"，也不是"审核中"） | 媒体列＝发布账号代号；「发布链接」＝自媒体链接；「网页链接」＝网页地址 |

**判定"已发布"需要两样东西都到位**：自媒体的公开链接（过审后回查得到）**和** FTP 上网页的公开地址
（用域名打开验证过）。

只到位一侧（例如自媒体还在审核、或网页还没传）→ 状态**停在 `已写作`**，把已经到手的那一侧链接先写上，
交付说明写明缺哪一侧、为什么。**不得为了让状态前进而填预览链、猜测链接，或留空冒充完成。**

固定链接列位置的意义：以后要统计"已发布多少篇"只需数链接列的非空数量，
不必依赖状态文字。

---

## 2. 回写白名单

只允许写下面这些单元格；**其余行、列、单元格一律不动**。

| 列 | 定位方式 | 允许写什么 |
|---|---|---|
| 编号列 | 表头含「编号」 | 该行稿件编号（整数或原样文本） |
| 状态列 | 表头含「状态」 | `已写作` / `已发布` |
| 媒体列（**仅当表里确实存在平台账号列时**） | 表头等于发布账号代号（如 `a-1`、`a-2`、`b-1`、`c-1`） | 实际使用的账号代号 |
| 末尾「发布链接」列 | 表头等于 `发布链接`（也认 `媒体链接`/`自媒体链接`/`链接`） | **自媒体**文章的公开链接；不存在时新增一列 |
| 末尾「网页链接」列 | 表头含「网页/网站/站点/FTP」且含「链接」 | **FTP 上该篇网页**的公开地址；不存在时新增一列 |

两个链接列是**两个不同的东西**，不要混在一列：
「发布链接」指向平台文章页（`www.sohu.com/a/…`、`www.toutiao.com/item/…`、`blog.csdn.net/…`），
「网页链接」指向自己服务器上的 `article-detail/<ID>.html`。

两列都不存在时按上面的顺序各追加一列（先「发布链接」后「网页链接」）；
已存在的列直接复用，**不会**重复新增，也不会去动中间已有的列。

**若表里没有平台账号列，就跳过媒体列这一项**：实测该总表后来被用户删掉了 a-1/b-1/c-1/c-2 四列。
此时**不得为了"记录账号"而擅自新增媒体列**——新增媒体列不在白名单内，
账号信息写在稿外说明里即可。两个链接列是白名单内唯一允许新增的列。

不允许：合并单元格、改列名、改其他行的状态、改表头、插在中间的新列、整列写入、写公式。

---

## 3. 定位规则

1. **优先按域名列定位**（表头含「域名」，值为 `某某.网址`）。域名在一行里是唯一的。
2. 域名命中多行 → **停下报告**，不要任选一行。
3. 域名命中 0 行 → 停下报告；不要退化成"按企业名模糊匹配"。
4. 允许用 `--row N` / `--number N` 显式指定，但执行前必须回读该行域名与用户说的对象核对一致。
5. 写回前先打印**写入前 / 写入后**的对照，供人核对。

---

## 4. 表头陷阱（实测踩过，务必先核对列义）

本类表格的表头**不能凭列字母或表头文字直接相信**。实测遇到过：

- 表头行里塞着**数据值**：D1 写着某企业全称、E1 写着某简称，而这两列实际上分别是「企业名称」「简称」，
  并没有自己的表头文字；
- 「企业名称」「简称」两列**无表头**，容易被误当成"域名/介绍"列；
- 「企业信息资料」列（F）只有部分行有值（实测 18/91），有值的行才是可写稿的行；
- 媒体列的**表头就是账号代号**（a-1 / b-1 / c-1 / c-2），不是"搜狐号""头条号"这样的平台名。

**同一条路径下的两次实测结构（结构被人改过，所以列义必须每次重核）**

| 时间 | 列结构 |
|---|---|
| 2026-10-16 上午 | A 编号 / B 状态 / C 域名 / D（无表头，实为公司名称）/ E（无表头，实为公司简称）/ F 企业信息资料 / G a-1 / H b-1 / I c-1 / J c-2 |
| 2026-10-16 下午（用户清理后） | A 编号 / B 状态 / C 域名 / **D 公司名称 / E 公司简称** / F 企业信息资料 / **G 发布链接**——平台账号列已删除，链接列固定在末尾 |

**结论：每次动手前重新打印一遍表头与样例。**「上次是这个结构」不构成依据，
本次就是因为结构从 11 列变成 7 列，旧的批量任务（含账号列）直接失效。

**因此：动任何格子之前，先逐列打印第 1~3 行样例 + 各列非空率与长度分布**，
据实际值判定列义，并在交付说明里记录判定结果。

**媒体账号与平台的对应也要实测确认**，不要相信注册表或表头标签：
实测出现过某账号在注册表里被标成 `sohu`，而配方声明与真机检查都指向 `mp.toutiao.com`
（该账号实为头条号），错误标签还导致登录流程被指向错误平台、把另一个平台的 cookie
写进同一个登录态文件，使原平台会话失效。

## 5. 幂等与冲突处理

| 情形 | 处理 |
|---|---|
| 已 `已发布`，又收到 `--status 已写作` | **不降级**，报告并跳过 |
| 已是 `已写作`，再写 `已写作` | 无差异，报告 `unchanged` |
| 链接列已有值，且与新链接不同 | **不覆盖**，报告冲突让人决定 |
| 状态列原值是旧口径（如 `已完成`） | 只改本次涉及的行；其余行保持原样，并在交付说明中如实指出差异 |
| 找不到状态列 / 编号列 / 域名列 | 停下报告，不猜列、不新建 |

---

## 6. 备份

写回前必须复制原表为：

```
<表名>-备份-<YYYYMMDD-HHMMSS>.xlsx
```

与原表同目录。备份路径要出现在交付说明里。备份文件**不参与后续回写**，
也不要删除既有备份。

---

## 7. 命令示例

```bash
# 稿件交付后
python scripts/table_writeback.py --xlsx "媒体发布表格.xlsx" \
    --domain "某某.网址" --number 76 --status 已写作

# 两个链接都到手后（自媒体 + 网页）
python scripts/table_writeback.py --xlsx "媒体发布表格.xlsx" \
    --domain "某某.网址" --status 已发布 --account a-1 \
    --link "https://www.sohu.com/a/1088485533_121778175" \
    --site-link "http://xinwen.wangbo.wang/article-detail/MEHFIITF.html"

# 自媒体还在审核，先只补网页链接（状态留在已写作）
python scripts/table_writeback.py --xlsx "媒体发布表格.xlsx" \
    --domain "某某.网址" --site-link "http://xinwen.wangbo.wang/article-detail/MEHFIITF.html"

# 一次写多行（按域名逐条定位；任一失败则整批不落盘）
python scripts/table_writeback.py --xlsx "媒体发布表格.xlsx" --batch batch.json --dry-run

# 只预览
python scripts/table_writeback.py --xlsx "媒体发布表格.xlsx" --domain "某某.网址" --dry-run
```

`--batch` 的 JSON 形状（`site_link` 可由 `scripts/publish_params.py` 生成的 `jobs.json` 直接带过来）：

```json
[
  {"domain": "tudu.网址", "number": 76, "status": "已发布", "account": "a-1",
   "link": "https://www.sohu.com/a/1088485533_121778175",
   "site_link": "http://xinwen.wangbo.wang/article-detail/MEHFIITF.html"}
]
```

退出码：`0` 全部成功（或 `unchanged`）；`1` 有失败/冲突；`2` 参数或表格结构问题。

**回写前先做身份核验**：批量回写用的 `batch.json` 最好由 `scripts/publish_params.py` 产出——
它会用「表格该行的企业名称必须出现在稿件里」做交叉核验，防止表传错时把链接写到别的企业那一行。
只按编号匹配是不安全的。

## 8. 交付说明里要写什么

回写之后，在交付说明（或稿外说明）里如实记录：

1. 备份文件路径；
2. 每行改了哪些列，写入前后的值（尤其两个链接列分别写了什么）；
3. 未写入的行及原因（例如"自媒体审核中、无公开链接，状态停在已写作，已先写网页链接"）；
4. 状态列里与本批口径不同的既有值（不擅自改写，只报告）；
5. 两个链接的来源与验证方式（自媒体链接来自哪次 backfill；网页链接用什么域名打开验证过）。
